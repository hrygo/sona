# 声音工坊：示例引导与双路径注册

## 1. 范围与依赖

本方案实现声音工坊的前端引导、Sona HTTP 代理及质量状态区分。服务端新链路依赖
[SpeechRail PR #46](https://github.com/hrygo/SpeechRail/pull/46) 的生成参考注册能力
（`0c403ab` 或后续兼容版本）。软件回归不代表真实 Apple Silicon 声纹、噪声或听感验收。

SpeechRail 独占 VoiceDesign、Base 和 ASR 模型。Sona 不安装、不下载、不启动这些模型，
也不接收前端指定的上游地址、模型仓库、凭据或本地参考文件路径。

## 2. 产品流程

```text
描述声音
  选择示例 → 编辑声音描述/参考朗读文本 → 可选草稿试听
  → 显式生成并保存 → 参考已核验 / 输出尚未评估
  → 检查 18 段合成输出 → 试听保存后的实际音色 → 手动确认使用

克隆声音
  录制自然声音 → 回听原始录音 → 核对实际朗读文本
  → 本地安全检查 → SpeechRail 参考预检 → 注册
  → 参考与输出分开显示 → 检查输出 → 试听 → 手动确认使用
```

保存不会关闭工坊、修改当前播报音色或自动发起耗时的 18 段输出检查。检查失败时音色
仍已保存；用户可复测，无需反复重新创建。新音色没有通过本轮输出检查和实际试听之前，
本工坊不提供绕过结果页的直接激活按钮。已有系统音色和旧 instruction 音色保持原契约。
此规则是工坊交互保护，不是服务端授权规则，也不阻止其他客户端显式使用注册音色。

## 3. 示例引导，而非专业术语输入框

`voiceDesignExamples.ts` 提供六种可编辑描述，均为文本模板，不是预制音频：

| 示例 | 使用场景 | 描述重点 |
| --- | --- | --- |
| 温柔知性 | 日常助手、交流 | 温暖清澈的成年女声、自然表达 |
| 技术讲解 | 技术分享、教程 | 清晰稳健的成年男声、语义停顿 |
| 简报播报 | 每日简报、摘要 | 干净明亮、节奏稳定、数字清晰 |
| 有声阅读 | 散文、故事旁白 | 温润醇厚、从容但连贯 |
| 明快陪伴 | 生活提醒、趣味解说 | 轻盈明亮、友好但不过度夸张 |
| 京味叙事 | 文化趣谈 | 轻微北京口音、克制顿挫，不模仿特定艺人 |

卡片展示场景和声音特征；选择后填入可编辑描述。已编辑的描述不会被另一个示例无声覆盖，
必须确认“替换描述”；自定义名称、参考文本保持不变。创建标签页切换保留本次会话草稿。
工坊关闭后草稿不会持久化到浏览器存储。

将两个容易混淆的输入分开：

- **声音描述**：希望声音怎样听起来。示例包含音色、发音、节奏与语气，页面给出简单修改提示。
- **参考朗读文本**：模型实际要读什么。默认中文文本可直接使用，20–240 字符；UI 在提交前校验。

首版中文优先。描述 UI 上限 1000 字符（比服务端 10000 的上限更收敛）。随机种子默认 42，
放在折叠高级设置中；不将固定种子描述成声纹一致性的保证。示例不保证产生专业播音效果，
最终声音仍由模型和实际验收决定。

## 4. 草稿、注册与输出的三个边界

`试听草稿` 调用 `/v1/voices/previews`，发送当前描述、参考文本、seed 和中文语言。
它不保存音色。`生成并保存可复用音色` 调用 `/v1/voices/designs`，服务端会重新生成参考，
不是将浏览器刚才播放的音频原样提交。因此草稿只作方向参考，保存后必须另行试听。

注册成功响应为：

```json
{"voice": {"id": "design_...", "mode": "clone", "creation": {"origin": "generated"}},
 "synthesis_validation": "unevaluated"}
```

示例只突出边界字段；完整 creation 还包括 artifact/revision/seed、三个 SHA-256 及前处理版本。
`voiceService.design` 校验真实响应结构、目标 ID、clone mode、generated provenance 与未评估状态；
缺少必要字段、旧接口响应或伪造的“已验收”包络均拒绝，不回退旧 metadata-only 创建接口。

`creation.origin=generated` 决定档案库显示“设计”，而 `mode=clone` 仍保留 Base 的推理语义，
不能为了 UI 分类将保存的音色改回 instruction mode。公开数据仅复制已知来源字段，不暴露路径。

## 5. 输入验收与输出验收分开

`VoiceCandidateReview` 分别持有参考与输出报告：

- `report.reference` 仅能使参考卡片显示“参考已核验”。
- 输出必须包含 `report.synthesis`。本工坊请求 `runs=3`，即六类探针各重复三次。
- 确认使用需要：pass、无失败码、至少 18 段生成完整、重复性证据为 true、存在 ASR 内容匹配
  指标，以及本次结果页的实际试听成功完成。报告阈值由 SpeechRail 判定，Sona 不另建声学评分器。
- 旧版仅三段或缺少 ASR 证据的 pass 标签不会被解释为本轮完整输出通过。
- 重测先清除旧输出通过状态与试听确认；失败或缺失报告不沿用旧的绿色状态。

生成计数使用“段已生成”，不称“测试通过数”。重复 PCM 相同只称“本轮重复样本一致”。
界面明确说明：信号/内容检查通过不等于独立声纹或降噪验收。旧音色缺少参考报告时显示
“尚未评估”，不补造证据。输出报告在本次客户端会话内更新；页面重载后以服务端实际返回为准。

## 6. 录音端电平与参考文本

浏览器请求关闭 AEC、降噪和 AGC；请求不是设备实际设置的证明，界面展示可读取的真实设置。
MediaRecorder 按支持情况选择 WebM/Opus、WebM 或 MP4，保留实际类型。此阶段仍是压缩容器
采集，不宣称已经实现 AudioWorklet 的无损 PCM 源采集。

提交不再调用客户端整段 RMS 归一，不把 Opus 转为 WAV 冒充源无损录音。浏览器检查只用于
静音、明显削波、实际解码时长等安全提示；检测到有效波形也不说明“没有噪声”。不能解码时
由服务端预检继续把关，预检不可用、未评估或拒绝时不发起注册。原始录音字节和电平保持不变，
由 SpeechRail 统一生成规范参考。旧音色不会因此自动重处理。

录音开始时固定提词文本，完成后允许用户改成**实际说出的内容**；不能通过切换提词器把另一段
文本错误绑定给已录制音频。用户应使用自己的声音或有授权的参考，自然清晰朗读即可，不要求
模仿播音员。先进降噪、神经 VAD、参考片段筛选及专业表达解耦仍由后续 SpeechRail 方案推进。

## 7. 恢复与生命周期

生成注册 ID 使用浏览器安全随机数，保持一次逻辑注册的 ID 和请求正文。按钮与同步 in-flight
锁共同防止双击。网络错误、5xx、ID 冲突可能意味着响应丢失而服务端已提交，冻结编辑并提供
“检查保存结果”或“使用同一 ID 重试”，不无声换 ID 重复创建。恢复时只接受该 ID、generated
来源、clone mode、名称和 seed 匹配的资产；这不是服务端持久化 Idempotency-Key 实现。

模式冲突与 ID 冲突分开提示。404/405 明确要求升级 SpeechRail，不调用旧创建接口降级。
模板操作不会发送音频或触发模型调用。推理期间禁用关闭、切换和并行动作；卸载组件时取消
请求与播放，播放 URL 在结束、错误和取消时释放，避免关闭后继续播报。取消浏览器等待不等于
撤销服务端事务，所以连接丢失后的保存状态必须先检查档案库。

保留助手静音租约、会议/字幕互斥校验与麦克风轨道清理。键盘焦点限制在模态区域，并在关闭后
恢复。明暗主题使用现有设计 token，小窗口允许内部滚动，示例选中状态有文字/边框双重表示。

## 8. 代理与验证

Sona `/v1/voices/designs` 为有界 JSON 代理：64 KiB 声明与实际字节双重限制、固定上游端点、
服务端配置的认证、上游状态/错误信封/request ID/Retry-After 保留。会议或字幕占用时先拒绝，
不把浏览器 Authorization 透传成上游凭据，不在 Sona 持久化参考音频。

回归覆盖示例选择与保护、草稿保持、精确请求、旧版本失败、注册恢复、重复点击、取消、
双质量状态、实际试听失败、原始字节保留、实际参考文本、代理大小/认证/模式冲突边界。
`.github/workflows/voice-studio.yml` 增加 UI 构建/测试及 Python strict/types/coverage 门禁，
数据库用 job 私有 PostgreSQL 服务及现有临时 schema 夹具，不连接用户数据。

本地 Chromium 使用实际组件、主题 CSS 与固定响应夹具检查明暗主题及 390px 宽窗口；
这验证布局/状态/键盘行为，不替代 Safari/WebKit、真实麦克风、真实 SpeechRail 模型和听感验收。


## 9. UX 分支闭环增量

[完整分支矩阵与复跑方式](voice-studio-ux-branch-audit.md) 是本流程的软件验收依据。

启用回调逐层返回 Promise，只有 `set_voice` 确认返回目标 voice 才显示成功；主界面选择
clone 音色同样进入检查/试听页。删除回调是真正执行删除，不再弹出第二个确认；异步失败
保留弹窗，删除当前音色之前必须先确认切换默认音色。删除失败后默认声音可能已经生效，
旧资产仍保留，此部分成功状态不能谎称原子事务。

每次试听、输出复测及取消都撤销旧确认；录音注册使用稳定 ID、原始音频和同一
`Idempotency-Key`。代理只允许有界 ASCII 键，认证仍来自服务端配置。上游幂等缓存不保证
跨进程或跨重启，因此恢复始终核对档案库；停止等待不等于撤销服务端保存。

用户可停止生成/检查等待、取消录音、从已保存设计返回原描述再创建新的 ID。
刷新失败保留列表；能力暂时消失时隐藏而不销毁编辑草稿，恢复后继续修改。
未提交录音、已修改描述或结果不确定时，关闭前明确确认，仅丢弃本地草稿，不删除远端资产。

声音操作等待已确认的助手静音；父子共享获取租约，关闭过程中先等待尚未完成的静音再恢复。
实际录音设置仍是可观测信息，不替代浏览器权限；录音器出错、空音频或设备中断不会卡死在
录音态。所有模态阻止全局切换模式、搜索和麦克风快捷键穿透；嵌套删除框自行处理 Escape。

只有软件分支矩阵、类型检查及 CI 通过，才能称本次代码回归通过；真实麦克风、Safari、
SpeechRail/MLX 听感、跨文本声纹和耗时/内存仍需目标机独立验收。
